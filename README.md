
# Dark Pattern Auditing Bureau
暗黑模式审计局：数字界面中的注意与交互冲突实验

## 1. 项目简介

本项目构建了一个基于浏览器的交互式注意实验平台，以模拟健身 App 作为实验场景，考察界面设计如何影响用户注意分配、视觉搜索和反应控制。

项目包含两个实验：

- 实验一：视觉搜索任务
- 实验二：UI Stroop 交互冲突任务

项目使用 HTML、CSS、JavaScript 实现，不依赖前端构建工具。

## 2. 实验一：视觉搜索

### 实验目的

考察干扰项数量与目标显著性如何影响用户寻找目标选项的效率。

### 实验设计

2 × 2 设计：

| 自变量 | 水平 |
|---|---|
| 干扰项数量 | 8 个 / 20 个 |
| 目标显著性 | 低 / 高 |

每个条件 10 个试次，共 40 个试次。

### 因变量

- 正确率
- 正确试次反应时
- 目标位置
- 干扰项数量
- 目标显著性

### 预测

1. 干扰项数量增加将延长视觉搜索反应时。
2. 高显著性目标将比低显著性目标更容易被发现。
3. 显著性可能减弱高干扰项条件下的搜索成本。

## 3. 实验二：UI Stroop

### 实验目的

考察按钮颜色与文字含义发生冲突时，用户是否受到非目标视觉线索的干扰，以及后果提示是否能够改善判断。

### 实验设计

2 × 2 设计：

| 自变量 | 水平 |
|---|---|
| 文字与颜色一致性 | 一致 / 冲突 |
| 后果提示 | 无 / 有 |

每个条件 10 个试次，共 40 个试次。

### 因变量

- 正确率
- 正确试次反应时
- 鼠标首次悬停时间
- 悬停次数
- 是否暴露后果提示

### 预测

1. 冲突条件下反应时更长、错误率更高。
2. 后果提示可能降低冲突条件中的错误率。
3. 后果提示可能使参与者更依赖文字语义而不是颜色线索。

## 4. 注视点与眼动估计

实验每个试次前均呈现独立空白注视屏。

眼动功能采用 WebGazer：
- 9 点校准，每点 5 次点击。
- 5 点独立验证。
- 验证采样在点击之前完成。
- 记录预测坐标、有效样本数和验证误差。

注意：
WebGazer 是基于摄像头的视线估计工具，不能等同于专业眼动仪。简单的坐标样本比例不能直接称为真实注视持续时间。本项目记录的是视线预测样本，不应直接解释为精确 fixation duration。

本项目不应将摄像头原始视频作为研究数据上传。

## 6. 本地运行

1. 将 `index.html`、`styles.css`、`app.js`、`README.md` 放在同一目录。
2. 双击 `index.html`。
3. 本地双击模式可以运行行为实验。
4. 摄像头眼动一般需要 HTTPS 或 localhost 安全上下文。

## 7. GitHub Pages 部署

1. 新建 GitHub 仓库。
2. 上传四个项目文件。
3. 打开仓库 Settings。
4. 进入 Pages。
5. 选择 Deploy from a branch。
6. 选择 main 分支和 root 目录。
7. 保存并等待部署。
8. 使用 GitHub Pages 提供的 HTTPS 地址访问。

摄像头权限需要 HTTPS 环境，并由参与者主动授权。

## 8. 统计分析建议

### 实验一

对干扰项数量和显著性进行 2 × 2 分析。

主要指标：
- 正确试次平均反应时
- 正确率

建议报告：
- 每个条件的均值和标准差
- 两个主效应
- 交互效应
- 效应量与置信区间

### 实验二

对一致性与后果提示进行 2 × 2 分析。

主要指标：
- 正确试次平均反应时
- 正确率

建议将反应时和正确率分别分析，不要仅依赖单一指标。

## 9. 数据质量与限制

- 参与者数量应在结果中如实报告。
- 不得将模拟数据当作真实参与者数据。
- 反应时异常值处理规则应在分析前确定。
- 对错误试次和极端反应时应分别说明处理方式。
- WebGazer 的视线估计受光照、摄像头、姿态和校准质量影响。
- 实验结果只能支持本实验操作条件下的推论，不能直接推广到所有商业 App。
