## 1. 实验背景与设计
本项目受现代 App 中常见的“暗黑模式（Dark Patterns）”启发，将其与工程心理学经典范式结合，设计了一款连续的用户体验审计游戏。

### 实验一：拒绝的代价（视觉搜索与显著性）
*   **范式**：基于 Treisman 特征整合理论与 SEEV 模型。
*   **任务**：在充满“立即领取”等诱惑干扰项的弹窗中，找到并点击“残忍拒绝”。
*   **条件**：基线（灰色小字） vs 改进（红色闪烁下划线）。
*   **因变量**：反应时 (RT)、错误率。
*   **预测（收数前）**：改进条件利用了“运动/颜色显著性”捕获注意，预期能显著缩短被试寻找拒绝按钮的 RT。

### 实验二：认知陷阱（UI Stroop 冲突）
*   **范式**：基于 Stroop 效应与 S-R（刺激-反应）相容性。
*   **任务**：在取消订阅弹窗中，根据**文字内容**点击“确认取消”（忽略按钮颜色）。
*   **条件**：兼容（取消为红色） vs 冲突/暗黑（取消为蓝色，继续为红色）。
*   **因变量**：反应时 (RT)、正确率。
*   **预测（收数前）**：颜色的自动化加工会干扰文字阅读，冲突条件下预期出现显著的 Stroop 效应（RT 延长，误触率上升）。改进条件加入 Hover 微交互提示以缓解冲突。

## 3. 数据收集与详尽分析说明
*   **被试来源**：共收集 >= 5 名（含本人）同学的数据，每人体验完整的 10 个试次。
*   **眼动数据（加分项）**：引入了 WebGazer.js，每次试次（trial）的点击瞬间，都会记录被试的 `(x, y)` 注视坐标并上传。
*   **数据分析呈现**：
    *   网页末页会实时读取个人的试次数据。
    *   计算基线条件与改进条件的**平均反应时 (Mean RT)**。
    *   计算实验二的 **Stroop 效应量**（冲突 RT - 兼容 RT）。
    *   **原论文对比**：经典 Stroop 实验的效应量通常在 80-100ms 左右。网页代码会自动将个人 UI Stroop 效应量与经典数值进行比对（如：“你的数据产生了 150ms 的冲突，说明复杂的图形界面放大了认知负荷”）。
    *   利用 Chart.js 生成了直观的柱状图供被试直观查看。
